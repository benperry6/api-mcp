### 请求头透传客户端原始 IP（第1次提交）

**需求**：MCP 走 ChatGPT HTTP 请求时，服务端向真实后端接口发起请求丢失用户原始 IP（后端拿到的是 MCP 云端 Pod 出口 IP），需把用户原始请求头携带的地址透传给后端。后端约定 header：`client-request-ip / client-request-url / client-request-host`（+ `client-request-user-agent`、`x-forwarded-for`）。

- **调用链路分析**：厘清 `ChatGPT → MCP HTTP transport(index.ts) → tool → http-client / raw fetch → 真实后端` 同步链路，定位「原始 IP 丢失」根因——服务端对后端「新建」请求，仅带 `Content-Type + CJ-Access-Token`，客户端信息未透传。
- **方案（对齐既有 directTokenStorage 模式）**：新增请求作用域 `AsyncLocalStorage` 上下文 `clientRequestStorage`；HTTP 入口从 `req.headers` 提取 → `run` 包裹处理；全部对外后端出口合并 `buildClientRequestHeaders()`。
- **TDD**：先写失败用例（client-request-context.test.ts）→ 实现模块 → 绿灯；再补 http-client 透传用例 + 真实本地后端 over-the-wire 集成用例。
- **落地文件**：
  - 新增 `src/utils/client-request-context.ts`
  - 改 `src/mcp-server/index.ts`（入口注入上下文）
  - 改 `src/api-client/http-client.ts`（主收口透传）
  - 改 `src/mcp-server/tools/{logistics,order,auth}.tool.ts`（3 处 raw fetch + 登录 fetch 透传）
- **验证**：`vitest run` 新增 15 用例全过、137/140 通过（3 为预存在失败，见下）、`npm run build` 成功、本地真实 HTTP 服务带 `x-real-ip` 冒烟正常。
- **提取规则**：`client-request-ip` 优先 `x-real-ip`，否则取 `x-forwarded-for` 首地址；`x-forwarded-for` 为空时用 `x-real-ip` 兜底放首位；数组头取首值；stdio 模式无上下文优雅降级。
